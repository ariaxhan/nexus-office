## Reconstructed incident classes

1. **Transient worker/process failure with recovery.** Office's four recent wedged health samples were each followed by alive; Tradition daemons remained alive in the recent liveness window. TBS watchdog recorded 70 recoveries after repair activity. These are resilience evidence, though not proof that every in-flight task reached the intended product state. Sources: `nexus-jobs/state/liveness.jsonl`, TBS `coordinator-watch.jsonl`.
2. **Repeated coordinator failures that eventually resumed.** TBS had 89 explicit nonzero ends and 68 later same-day success ends; Matra had 25 and 23 respectively. Matra logs show repeated DNS `ENOTFOUND` failures on 21 Sep, then later work; 24 Sep logs show `Not logged in` and a provider rate limit. The pre-fix Matra launcher used one provider and stopped a run; later ticks could succeed but did not provide same-run cross-provider recovery. Sources: each `coordinator-runs.jsonl`, referenced `.coordinator-out` logs, `scripts/coordinator/run.sh`.
3. **Silent or misleading success/health.** Office issue #161's Open action claimed success without a visible document switch; the installed-app route was subsequently repaired and verified. Matra's release runner has 747 nonzero job attempts but later success and release receipts; treating its raw attempt count as failed releases would be wrong. TBS prod-probe failures included inability to post a Buzz alert; a probe failure cannot be treated as visible escalation. Tower's older liveness check remained wedged for multiple samples before recovery. Sources: issue #161, jobctl receipts/liveness, TBS prod-probe receipts.
4. **Accepted email followed by companion failure and duplicate send.** On 24 Sep midday, the shared email log records Gmail acceptance at 12:03 PDT, a Claude spend-limit response in the post-send taper step, a 12:04 retry, and second Gmail acceptance at 12:07. The unified email ledger has two `success=true` midday rows that local day. This recurred on earlier local dates. Pre-existing commit `92dd059da` made post-send taper failure nonfatal and `2fa48e319` added Codex continuation; commit `95f309081` now prevents re-delivery even if a later companion step or process fails. Sources: `_meta/logs/email-2026-09-24.log`, `_meta/logs/runs.jsonl`, `runner/email-runner.sh`, `send-gmail.py`.
5. **Work correctly refused by verification, but not complete.** Clay #3 produced code and a PR, then review rejected contradictory retention behavior and missing audio-source capture. Office issue flights entered `CLOSED:no_change` and pending retry because there was no landed commit. These are safer than false completion, but neither is a finished issue. Source: Nexus `ledger.sqlite` events `work.pending`, `flight.terminal`, `work.review`.
6. **Feed verification failure then successful operation.** Two 23 Sep `com.aria.office-feed` attempts failed on SQLite parameter binding, then 38 successful hourly receipts and 83 published posts followed. The 179 rejected model runs are recorded evidence-gate decisions. Sources: jobctl receipts, `office-feed.sqlite3` posts/model_runs.
7. **Human intervention remains necessary in bounded cases.** TBS watchdog logged five escalations; TBS holds include sensitive release windows; Tower local commits/review failures require a decision or repair. Email ambiguous Gmail acceptance must fail closed until Sent is reconciled; this is preferable to another duplicate send. Sources: TBS `coordinator-watch.jsonl`, `coordinator-holds.jsonl`, Tower events, `send-gmail.py`.

## Current gate and candidate status

The clean-commit Office gate passed from `403a04a`: `npm run verify` returned 0, with 1,428 Python tests across 91 test files, four Node tests, a matched complexity baseline, and Swift tests. The runner now uses Python 3.12 in isolated test-file processes; the empty fixture file is skipped, the TBS fake clock is explicitly enabled in its test, and the null-ledger lane fallback is preserved. The installed Office Open path and live Find results were verified as described above. A **stability candidate** is marked for the repaired paths, subject to subsequent normal-operation regression evidence. Ask physical interaction, the next automatic Find refresh, Feed/Tower longer recovery windows, and the next podcast render remain unproven; the candidate does not assert those paths are resilient.

The subsequent observation window should watch normal sends, Matra coordinator completions, Tower issue transitions and Office action receipts. It is regression evidence for the repairs above. It does not replace April–September email history or the retained coordinator/job histories, and it need only be reset for behavior materially changed by a fix.
